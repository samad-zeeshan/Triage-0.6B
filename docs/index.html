Project

Triage-0.6B

A small language model (600 million settings, small enough to run on one desktop) that reads a support email and writes down three things: which team it goes to, how urgent it is, and the account number if the email states one.

For the person who opens the support inbox in the morning and has to sort it before anyone can start work.

Visual explanation, no model runs on this page Open the numbers behind this page

The inbox fills faster than anyone can sort it

It is Monday morning and the support inbox is full. Before anybody can fix anything, a person has to open each email and make three calls: which team owns it, whether it can wait, and which customer it is.

Sorting is slower than answering. While someone reads a polite question about invoices, an email saying the payment system is down waits its turn further up the list.

A large model in the cloud can do this sorting well, but it charges for every email and it needs your customers' messages sent off your machines to do it.

Three things worth taking from that

  • It answers in fields, not in sentences. All 1,200 test answers came back as a line a computer can read, both before and after training.
  • The skill was not already in there waiting for a better prompt. Before training the small model was worse at judging urgency than a rule that ignores the email entirely. Training put the judgement in.
  • It runs on one computer, with nothing sent anywhere. The screenshot above is the model answering inside a desktop app, with no cloud service involved.

Urgency went from worse than guessing to 87 in 100

All three numbers below were measured the same way: on 1,200 emails that were kept back and never used for training, counting an answer right only when it matched the answer key exactly.

87.3% of urgency calls were exactly right after training, up from 38.3% before it. Source: results/confusion_matrices.txt. Method: exact match against the answer key, over all 1,200 emails held back from training.
42.4% is what you score by ignoring the email and always saying "high". The model before training scored 38.3%, which is worse than that. Source: results/confusion_matrices.txt. Method: 509 of the 1,200 emails really are high urgency, so a rule that always says high gets 509 right.
89.7% of emails were sent to the right team after training, up from 64.2%. Always saying "Technical Support" scores 63.8%. Source: results/confusion_matrices.txt for 89.7% and 64.2%, README.md for the 63.8% always-guess figure. Method: exact match against the answer key, over the same 1,200 emails.

What it does not do

Four things this number does not cover

Written down here so nobody has to find them out later.

  • It only knows five teams and three urgency levels, because that is the whole list it was shown. An email that belongs somewhere else has nowhere to go.
  • The answer key was written by a larger model, not by a support team. 87.3% means it agrees with that larger model, which is not the same as being right.
  • Pulling the account number out of the email is not covered by the 87.3% figure. That figure counts urgency only, and the account number was never scored.
  • The emails are made up, not real customer traffic, and this is one training run with one random seed. Nobody has measured how much the result would move on a second run.

Six steps, start to finish

  1. Take a public collection of support emails, written in more than one language, and set aside 2,500 to learn from and 1,200 to test with.
  2. Have a large model read every email and write down the three fields. Those answers become the answer key. See the notebook that builds the key.
  3. Add a sentence stating an account number to about 7 emails in 10, so there is something real to pull out and the other 3 in 10 teach it to answer "none".
  4. Show the small model the 2,500 examples twice over, until it copies the shape of the answers. See the notebook that trains and scores it.
  5. Ask it the 1,200 questions it has never seen, and count how many answers match the key exactly. That count is the whole of the proof above.
  6. Save a compressed copy that opens in an ordinary desktop app, so it answers on one machine with nothing sent anywhere.
